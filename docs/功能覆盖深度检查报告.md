## 4. 行索引系统（关键差异）

### 架构对比

| 层级     | C++ 架構              | Rust 实現                       | 状态 | 备注                                                |
| -------- | --------------------- | ------------------------------- | ---- | --------------------------------------------------- |
| 第一层   | 直接索引 (u32, ≤1M行) | `direct_offsets: Vec<u32>`      | ✅   | 完整实现                                            |
| 第二层   | 扩展索引 (u64, >4GB)  | `extended_offsets: Vec<u64>`    | ✅   | 完整实现                                            |
| 第三层   | 分块索引 (128KB/块)   | `chunks: Vec<ChunkIndex>`       | ⚠️   | 已填充状态，并已用于按位置查询范围裁剪              |
| 分块限制 | 8,388,608 (8M)        | 8,388,608                       | ✅   | 已修正为 C++ 同量级                                 |
| 溢出处理 | `overstep` 字段       | `overstep_pos` 记录首个溢出位置 | ✅   | 已记录，并用于超过最后 chunk 后的按位置查询范围裁剪 |
| 缓存优化 | `lastline/lastpos`    | `cached_line`/`cached_pos`      | ✅   | 完整实现                                            |

### 查询函数对比

| 函数           | C++ 实现       | Rust 实现           | 状态 | 备注                                                 |
| -------------- | -------------- | ------------------- | ---- | ---------------------------------------------------- |
| `GetLindexPos` | 完整三层查找   | `get_line_pos()`    | ⚠️   | 仍查直接/扩展精确偏移，未按 C++ 从 chunk 起点回扫    |
| `GetLineByPos` | 完整三层二分   | `get_line_by_pos()` | ⚠️   | 已使用 chunk 裁剪二分范围，但仍依赖完整偏移数组      |
| 行长度计算     | 减 `\n`/`\r\n` | 扫描时记录内容长度  | ✅   | 已覆盖 CRLF、UTF-16LE/BE 与 UTF-32LE/BE 原始字节偏移 |

### 关键问题

- **分块查询仍未完全等同 C++**：`chunks` 已在扫描时填充，`get_line_by_pos()` 已使用 chunk 与 `overstep_pos` 裁剪二分范围，但尚未复刻 C++ 从 chunk 起点回扫目标行的完整路径
- **性能结构差异**：当前直接索引与扩展索引可保持百万行后的正确性，按位置查询已能利用 chunk/overstep 缩小搜索范围，但行号到位置查询仍直接依赖完整偏移数组
- **已修复正确性缺口**：`CHUNK_COUNT_MAX`、CRLF 行长度、UTF-16LE/BE 与 UTF-32LE/BE 换行宽度、百万行后续偏移保存、chunk 填充、按位置查询范围裁剪与 overstep 溢出段范围裁剪均已补单元测试

## 8. 当前结论

Rust 版本已覆盖常见文件加载、扫描、行定位、编码检测与读取场景。2026-05-20 的修复消除了几处会导致行为不一致或资源浪费的问题：CRLF、UTF-16LE/BE 与 UTF-32LE/BE 原始字节偏移、UTF-32 BOM、重扫 API、百万行后续偏移、chunk 填充与按位置查询范围裁剪、overstep 溢出段范围裁剪、mmap 读取窗口动态重映射、`ReadFileDataLLineCut` 对应读取语义、UTF-8 消费字节数、加载状态诊断、扫描完成通知等待、扫描中止、后台扫描前的整块数据复制，以及大文件 clone/save/append/concatenate 的慢路径。

后续开发应优先进入结构性能力补齐：完整 C++ 风格 chunk 回扫路径与超大文件扫描窗口化。C FFI 已具备核心调用闭环，后续可继续补独立 C 集成测试和发布用头文件。
