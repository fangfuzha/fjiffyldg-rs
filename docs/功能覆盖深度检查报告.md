## 4. 行索引系统（关键差异）

### 架构对比

| 层级     | C++ 架構              | Rust 实現                    | 状态 | 备注                  |
| -------- | --------------------- | ---------------------------- | ---- | --------------------- |
| 第一层   | 直接索引 (u32, ≤1M行) | `direct_offsets: Vec<u32>`   | ✅   | 完整实现              |
| 第二层   | 扩展索引 (u64, >4GB)  | `extended_offsets: Vec<u64>` | ✅   | 完整实现              |
| 第三层   | 分块索引 (128KB/块)   | `chunks: Vec<ChunkIndex>`    | ❌   | **定义但未填充/查询** |
| 分块限制 | 8,388,608 (8M)        | 8,388,608                    | ✅   | 已修正为 C++ 同量级   |
| 溢出处理 | `overstep` 字段       | `overstep_pos` 定义          | ❌   | **定义但未使用**      |
| 缓存优化 | `lastline/lastpos`    | `cached_line`/`cached_pos`   | ✅   | 完整实现              |

### 查询函数对比

| 函数           | C++ 实现       | Rust 实现           | 状态 | 备注                                                 |
| -------------- | -------------- | ------------------- | ---- | ---------------------------------------------------- |
| `GetLindexPos` | 完整三层查找   | `get_line_pos()`    | ⚠️   | 仅查直接/扩展，未使用分块                            |
| `GetLineByPos` | 完整三层二分   | `get_line_by_pos()` | ✅   | 完整二分实现                                         |
| 行长度计算     | 减 `\n`/`\r\n` | 扫描时记录内容长度  | ✅   | 已覆盖 CRLF、UTF-16LE/BE 与 UTF-32LE/BE 原始字节偏移 |

### 关键问题

- **分块索引未真正实现**：`chunks` 和 `overstep_pos` 字段仍未被 `build_from_data()` 填充或被查询函数使用
- **性能结构差异**：当前直接索引与扩展索引可保持百万行后的正确性，但尚未复刻 C++ 的第三层 chunk 查询路径
- **已修复正确性缺口**：`CHUNK_COUNT_MAX`、CRLF 行长度、UTF-16LE/BE 与 UTF-32LE/BE 换行宽度、百万行后续偏移保存均已补单元测试

## 8. 当前结论

Rust 版本已覆盖常见文件加载、扫描、行定位、编码检测与读取场景。2026-05-19 的修复消除了几处会导致行为不一致的正确性问题：CRLF、UTF-16LE/BE 与 UTF-32LE/BE 原始字节偏移、UTF-32 BOM、重扫 API、百万行后续偏移、`ReadFileDataLLineCut` 对应读取语义、UTF-8 消费字节数、加载状态诊断、扫描完成通知等待和扫描中止。

后续开发应优先进入结构性能力补齐：真正的 chunk 索引，以及 windowed mmap 与大文件 I/O 优化。C FFI 已具备核心调用闭环，后续可继续补独立 C 集成测试和发布用头文件。
