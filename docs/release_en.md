# Release Guide

[Chinese](release.md)

This document describes the release process, versioning rules, and pre-release checks for the `fjiffyldg` crate.

## Versioning Rules

The project is currently in the `0.x` phase, but it still follows the core ideas of semantic versioning:

- Prefer bug fixes that preserve the existing API and C ABI;
- Add new capabilities in a backward-compatible way when possible;
- When a breaking change is unavoidable, bump the pre-1.0 minor version and describe the impact clearly in the changelog.

## Pre-Release Checks

Before creating a tag, run at least the following commands:

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
cargo doc --all-features --no-deps
pwsh -File scripts/check_c_abi.ps1
cargo package --list --allow-dirty --registry crates-io
cargo publish --dry-run --allow-dirty --registry crates-io
```

These checks cover formatting, static analysis, tests, documentation, C/C++ ABI smoke, and crates.io package readiness.

## Release Steps

1. Update [CHANGELOG_EN.md](CHANGELOG_EN.md) and [CHANGELOG.md](CHANGELOG.md) with the release notes.
2. Make sure [include/fjiffyldg.h](../include/fjiffyldg.h) has been regenerated by `cbindgen` and verified by `scripts/check_c_abi.ps1`.
3. Confirm that [docs/CONTRIBUTING_EN.md](CONTRIBUTING_EN.md), [docs/SECURITY_EN.md](SECURITY_EN.md), and [docs/DEVELOPMENT_TODO_EN.md](DEVELOPMENT_TODO_EN.md) do not contain release blockers.
4. Create a version tag such as `v0.1.1`.
5. Let `.github/workflows/release.yml` handle cross-platform verification, header validation, and publishing on tag pushes.
6. After publishing, add a short note and any required attachments to the GitHub Release page.

## What to Call Out

If the release includes any of the following, mention them explicitly in the release notes:

- C API signature or return-value changes;
- Header generation rule changes;
- File loading, scanning, encoding detection, or read-path changes;
- Platform support changes;
- Any behavior change that affects FFI callers.

## Yanking

If a published version is found to have a serious issue, prefer yanking it on crates.io and describe the reason and replacement version in the changelog and GitHub Release notes.
