# C API Usage Guide

[中文文档](c_api_usage.md)

This guide explains how to use the Fjiffyldg C ABI from C or C++ projects. The public header is generated from the Rust FFI source with `cbindgen` and should not be edited manually.

## 1. Generate the Header

Install `cbindgen`:

```powershell
cargo install cbindgen --locked
```

Generate the public header:

```powershell
pwsh -File scripts/generate_c_header.ps1
```

The generated file is [include/fjiffyldg.h](../include/fjiffyldg.h). Before release or commit, verify that the generated header is up to date:

```powershell
pwsh -File scripts/generate_c_header.ps1 -Verify
```

[cbindgen.toml](../cbindgen.toml) controls the export macro, include guard, C++ compatibility wrapper, and function declaration format.

## 2. Build the Rust Library

Build the dynamic or static library:

```powershell
cargo build --release
```

`Cargo.toml` enables `cdylib` and `staticlib`, so the release directory contains platform-specific dynamic and static outputs. On Windows this usually includes `fjiffyldg.dll`, `fjiffyldg.dll.lib`, or `libfjiffyldg.a`; on Linux/macOS this usually includes `libfjiffyldg.so`, `libfjiffyldg.dylib`, or `libfjiffyldg.a`.

## 3. Compile a Caller

C callers include the generated header directory and link the release artifact. Example:

```bash
cc -std=c11 -I include app.c -L target/release -lfjiffyldg -o app
```

C++ callers can include the same header:

```bash
g++ -std=c++17 -I include app.cpp -L target/release -lfjiffyldg -o app
```

The repository smoke check first verifies that the header is generated by `cbindgen` and up to date, then compiles C and C++ smoke inputs. It also builds the release dynamic library, links C/C++ smoke executables, and runs the minimal call path:

```powershell
pwsh -File scripts/check_c_abi.ps1
```

The script covers basic availability of loading, scanning, line queries, reads, huge mmap, encoding helpers, and the C++ RAII wrapper. On Windows it temporarily adds `target/release` to `PATH` so the smoke executables can load `fjiffyldg.dll`.

## 4. Handle Lifetime

The C API uses an opaque `fjiffyldg_ptr` handle. Callers hold the pointer but never access its fields.

```c
#include "fjiffyldg.h"

int main(void) {
    fjiffyldg_ptr fm = fjiffyldg_create();
    if (fm == 0) {
        return 1;
    }

    fjiffyldg_clear(fm);
    return 0;
}
```

Lifetime rules:

- Create a handle with `fjiffyldg_create()`.
- Release every successfully created handle exactly once with `fjiffyldg_clear()`.
- Most queries return an error code or null pointer when passed a null handle.
- Do not copy, free, or write through internal buffer pointers returned by the API.

## 5. Load, Scan, and Query Lines

```c
#include "fjiffyldg.h"
#include <stdint.h>
#include <stdio.h>

int main(void) {
    fjiffyldg_ptr fm = fjiffyldg_create();
    if (fm == 0) {
        return 1;
    }

    int code = LoadAndScanFile(fm, "large_file.txt");
    if (code != 0) {
        fjiffyldg_clear(fm);
        return code;
    }

    WaitFileScanTaskFinished(fm);

    long long lines = GetFileLineCount(fm);
    long long pos = GetFileLinePos(fm, 0);
    long long len64 = GetFileLineLength(fm, 0);
    printf("lines=%lld first_pos=%lld first_len=%lld\n", lines, pos, len64);

    fjiffyldg_clear(fm);
    return 0;
}
```

Common functions:

| Function                   | Purpose                                                    |
| -------------------------- | ---------------------------------------------------------- |
| `LoadAndScanFile`          | Load a file and start background line scanning             |
| `LoadFileOnly`             | Load a file without line scanning                          |
| `WaitFileScanTaskFinished` | Wait for background scanning to finish                     |
| `BackstageRequestStop`     | Request scan cancellation and clear the current line index |
| `GetFileLineCount`         | Return total line count                                    |
| `GetFileLinePos`           | Return the byte offset of a line                           |
| `GetFileLineLength`        | Return content length without line endings                 |
| `GetFileLineIndex`         | Find the line containing a byte position                   |

## 6. Read Data

`ReadFileData` uses `len` as an input/output parameter: before the call it is the requested maximum length; after the call it is the actual returned byte count.

```c
unsigned int len = 1024;
const char *data = ReadFileData(fm, 0, &len);
if (data != 0) {
    fwrite(data, 1, len, stdout);
}
```

Buffer rules:

- Returned pointers are owned by `fjiffyldg_ptr`.
- The next read may overwrite the previous read result.
- Copy data immediately if it must outlive the next API call.
- Never call `free()` on returned pointers.

`ReadFileDataLLineCut` follows the C++ reference semantics: it batches short lines and truncates long lines at the 4 KB cutoff. `ReadFileDataEndOfLine` reads from a byte position to the current line end.

## 7. Huge mmap Pointer

`GetFileMappedHuge` returns a real file mmap pointer held by the handle and writes the mapping size to `bufferSize`.

```c
long long size = 0;
const char *mapped = GetFileMappedHuge(fm, "large_file.txt", &size);
if (mapped != 0) {
    /* mapped[0..size) is valid until ClearHugeBuffer or fjiffyldg_clear. */
    ClearHugeBuffer(fm);
}
```

Notes:

- The pointer is read-only; callers must not write through it.
- The pointer remains valid until `ClearHugeBuffer(fm)`, the next `GetFileMappedHuge`, or `fjiffyldg_clear(fm)`.
- Empty files, open failures, or mmap failures return a null pointer and set `bufferSize` to 0.

## 8. Encoding and File Helpers

| Function               | Purpose                                              |
| ---------------------- | ---------------------------------------------------- |
| `CheckTextASCII`       | Check whether a byte range is all ASCII              |
| `CheckWholeTextUtf8`   | Validate a full byte range as UTF-8                  |
| `CheckExtractTextUtf8` | Sample text ranges for UTF-8 validity                |
| `GetUtf8TextCharCount` | Count UTF-8 characters and advance the input pointer |
| `GetFileSizeByteCount` | Return file size                                     |
| `ToCloneFile`          | Copy a file                                          |
| `ToSaveFile`           | Save a buffer to a file                              |
| `ToAppendFile`         | Append a buffer to a file                            |
| `ToConcatenateFile`    | Append the second file to the first file             |

## 9. Error Codes

Most functions returning `int` use 0 for success and non-zero values for errors. Common codes map to Rust internal errors:

| Code | Meaning                           |
| ---- | --------------------------------- |
| `0`  | Success                           |
| `-1` | File not loaded or invalid handle |
| `1`  | File inaccessible                 |
| `2`  | Stream error                      |
| `3`  | Memory mapping error              |

Pointer-returning functions usually use null for failure and set output parameters to 0 or preserve diagnostic context.

## 10. Maintaining Generated Files

After changing `#[no_mangle] extern "C"` signatures or C API comments in [src/ffi.rs](../src/ffi.rs), run:

```powershell
pwsh -File scripts/generate_c_header.ps1
pwsh -File scripts/check_c_abi.ps1
```

If `-Verify` fails, [include/fjiffyldg.h](../include/fjiffyldg.h) is out of sync with the Rust FFI source or [cbindgen.toml](../cbindgen.toml). Regenerate and commit the header.
